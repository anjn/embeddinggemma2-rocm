# アプリケーションAPI

出力は行優先のFP32配列`[batch,768]`で、L2正規化済みです。画像入力は連続したuint8 RGB配列`[batch,height,width,3]`、要求バッチは1〜128です。ネイティブAPIは同期呼び出しで、CPU出力を書き終えてから戻ります。入力・出力バッファの所有権は呼び出し元に残ります。

Cでは`eg2/eg2.h`をインクルードして`eg2`にリンクし、コンテキストを作成してから`eg2_encode_images`、`eg2_encode_texts`、`eg2_encode_tokens`を呼び出します。最後に`eg2_destroy`で解放します。エラーは戻り値と呼び出し元の文字列バッファで返します。C++の`eg2::Context`はコンテキストを所有し、エラー時に例外を送出します。

Pythonの`Embedder`は`with`と`close()`に対応します。テキストの`prompt='query'`は`task: search result | query: `、`prompt='document'`は`title: none | text: `を先頭に付けます。`prompt=None`では付けません。`max_length`は最大8192で、超過する入力はエラーにします。入力系列長を処理できるプロファイルを準備してください。

## HTTP形式

```json
{"model":"embeddinggemma-2","input":["猫","街並み"],"input_type":"query","encoding_format":"float"}
```

画像は次の構造で指定します。data URLは実際のbase64画像データへ置き換えてください。

```json
{"model":"embeddinggemma-2","token_budget":70,"input":[{"content":[{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}]}]}
```

各要素に画像を1枚指定します。テキストと画像を同じ要求へ混在させることはできません。画像はbase64のdata URLに限定し、外部URLは取得しません。同一要求の画像は同じ縦横サイズに揃えます。`encoding_format='base64'`ではベクトルをリトルエンディアンFP32のバイト列として符号化します。`dimensions`は768のみです。

入力エラーは400、未準備のプロファイルは503、キュー満杯は429を返します。キュー上限の既定値は32、リクエスト本文の上限は256 MiBです。GPU処理は直列です。`/ready`は準備状態と実行情報、`/health`はプロセスの稼働状態を返します。認証と複数GPUのスケジューリングは提供しません。

コンテキストは画像用とテキスト用の実行プロファイルを各1つ保持します。budget、バッチや系列長の切り替えでは、GPUプログラムの解放と再ロードが発生する場合があります。混在する実運用では、この時間も含めて測定してください。比較表は同じプロファイルを繰り返す定常状態の測定です。

画像の前処理は、半ピクセル座標のバイリニア補間、1/255スケーリング、16×16パッチ抽出を統合しています。元のバイキュービック・アンチエイリアス処理とは異なるため、高速化プロファイルの採用時にはアプリケーションの画像でも検索精度を確認してください。

この版では、budget 280の画像要求と準備時の実行バッチを32枚以下に制限します。gfx1150で直接batch 128と32枚ずつの4分割の両方が安定性検証に失敗したため、33枚以上の要求には`EG2_UNSUPPORTED`（Pythonでは`UnsupportedProfile`、HTTPでは503）を返します。32枚以下の要求に分けて送信してください。budget 70・140は128枚まで受け付けます。
