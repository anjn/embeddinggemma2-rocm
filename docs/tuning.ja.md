# GPU別チューニングと精度確認

`eg2 tune --model models/google --output artifacts/tuning --budget 70 --batch 4 --vision-batches 1 4`で、ROCmが対応するAMD GPU向けにカスタムHIPカーネルを探索します。GEMMとAttentionには既存のライブラリ実装を使います。

各Vision内部バッチについて、ブロックサイズ64・128・256・512、GELUと前処理のベクトル幅1・2・4・8・16、QK/RoPEと正規化のレーン数4・8・16・32・64を候補にします。GPUの制限、waveサイズ、整除条件に合わない候補は除外します。packed QKは16レーンです。単体の数値検証を通った各系列の最速候補について、適用の有無とAttentionの通常実行・分割実行を組み合わせ、モデル全体を測定します。既定の実装も比較対象に含めます。全カーネル設定の直積を測る方式ではありません。

探索全体に時間上限は設けず、定義した有限の候補集合を最後まで処理します。コンパイルとGPU実行はプロセスを分け、個別にタイムアウトを設定します。各候補の結果を保存するため、同じ引数に`--resume artifacts/tuning/tuning/SESSION`を加えると再開できます。GPU、ソフトウェア、カーネルソース、探索条件が一致する必要があります。実行中に中断したカーネルは失敗として記録し、GPUの動作確認にも失敗した場合は停止します。`--cache-dir`には既存のコンパイル結果を指定できます。

モデル全体の測定では候補の順序を逆にした2巡を実行し、同じバイリニア前処理を使う独立したCPU FP32の出力と比較します。参照値は1画像ずつ計算してメモリ使用量を抑えます。入力画像の順序を逆転させる検査も行います。入力は事前に512×288へ揃えた16:9のRGB画像です。

最小コサイン類似度0.995以上は数値の予備検査であり、検索精度の保証ではありません。現在のツールは`activated=false`として候補を保存し、運用中のデータを置き換えません。採用前に固定の256画像・1280キャプションをすべて使い、元のFP32モデルに対するR@1低下が画像検索・テキスト検索の両方で1ポイント以内であることを確認してください。速度測定用の乱数画像では検索精度を評価できません。

gfx1150専用処理はVisionのBF16化、GELU・QK/RoPEカーネル、配置変更、正規化の統合、MIGraphX分割実行、ネイティブAttentionを組み合わせます。従来の既定設定はbudget 70、16:9、Vision内部バッチ16が対象です。自動探索では他のプロファイルにも形状別の設定を試しますが、コンパイラの出力構造が非対応なら候補を除外します。グラフ構造と出力の対応を検査し、失敗時は通常のコンパイル結果を残します。コンパイル成功だけで精度確認済みとは判断できません。

`tests/`にトークナイザー、画像、テキストのGPU一致確認スクリプトがあります。各スクリプトの`--help`で引数を確認してください。CPUのHTTPテストはモックを使うため、GPUの計算精度は検証しません。

`tools/evaluate_quality.py`はローカルの画像・キャプション一覧を受け取り、元のCPU FP32モデルとの比較結果をJSONへ保存します。各画像には一意の`id`、相対パスの`image`、`captions`配列を指定します。データ件数と入力ハッシュを検査し、参照値をキャッシュできます。[英語版](tuning.md)に実行例があります。

`tools/activate_profile.py`は、全件の精度検査に合格し、候補のパスとプロファイルが一致するレポートを要求します。新しい出力先へコピーし、既存の運用データは変更しません。

準備とチューニングを行うGPUは`HIP_VISIBLE_DEVICES`で選択できます。可視デバイスの先頭を使います。ネイティブコンテキストとサーバーはデバイス番号も指定できます。別のGPUアーキテクチャでは再コンパイルし、精度と速度を確認してください。

`python tools/prepare_quality_dataset.py`で固定評価データを再現できます。Flickr8kの固定リビジョンのtest splitをファイル名順に並べ、NumPyのseed 20261016で256件を重複なく選び、各5件のキャプションを使います。画像全体を528×288の灰色余白内へ収め、評価時に512×288へ事前リサイズします。評価には`--manifest artifacts/quality-data/manifest.json --data-root artifacts/quality-data`を指定します。写真とキャプションはGit対象外のローカルデータとして保存します。取得元の利用条件を確認してください。

画像とテキストの両方を評価する前に、採用候補のディレクトリへテキスト用プロファイルも準備してください。候補のパスはチューニング結果の`selected.bundle`に記録します。

モデル全体の採否は、R@1低下が両方向で1ポイント以内かどうかで判定します。前処理も異なる元のFP32実装に対するコサイン類似度は、測定値として併記します。チューニング中の0.995以上という数値検査は、同じバイリニア前処理を使う通常精度プロファイルとの比較に適用します。

この版では、budget 280の画像要求と準備時の実行バッチを32枚以下に制限します。gfx1150で直接batch 128と32枚ずつの4分割の両方が安定性検証に失敗したため、33枚以上の要求には`EG2_UNSUPPORTED`（Pythonでは`UnsupportedProfile`、HTTPでは503）を返します。32枚以下の要求に分けて送信してください。budget 70・140は128枚まで受け付けます。

## 探索結果の公開と再利用

選択されたバンドルにテキストプロファイルを追加し、全件の検索精度検査を通した後、設定を出力します。

```sh
eg2 export-tuning --profile artifacts/tuning/tuning/SESSION/profile.json \
  --quality artifacts/quality.json --output profiles/gpus/gfx1150/budget70-b4.json
```

JSONを`profiles/gpus/`へ保存してコミットすると、Python配布物にも含まれます。保存するのは設定と検証結果で、重み、コンパイル済みバイナリ、ローカルパスは含めません。他の環境で通常の`eg2 prepare`を実行すると、一致する設定を選んで現地でコンパイルします。自動探索は実行しません。GPU、ソフトウェアの版、モデルとプロファイル、カーネルソースのハッシュを照合し、一致する設定がなければ理由を表示して既定の処理を使います。`--tuning-profile PATH`は指定ファイルとの一致を要求し、`--no-presets`は自動選択を無効にします。

## 画像・テキスト間のメモリ共有

準備済みバンドルを新しいディレクトリへ変換します。

```sh
eg2 share --bundle artifacts/my-gpu --output artifacts/my-gpu-shared
eg2 serve --bundle artifacts/my-gpu-shared
```

変換元は変更しません。schema 2では、同一の重みを共有し、作業領域を最大プロファイルに合わせて一度だけ確保します。画像の実行グラフ、テキストモジュール、プロファイル情報は保持します。同じコンテキスト内の呼び出しは直列実行し、切り替え時に各入力を復元します。サーバーは起動時に全プロファイルを準備します。組み込み用途では`Embedder.prepare()`、`Context::prepare()`、`eg2_prepare()`を呼び出せます。

プロファイルごとに重みと作業領域を丸ごと複製することはなくなります。ただし、異なる精度・配置の重み、グラフやコードの管理情報、最大プロファイルの作業領域は必要です。RGB入力領域は入力解像度に応じて拡張されます。別コンテキストや別サーバーワーカーは、それぞれGPUメモリを確保します。`capabilities.memory`で重み、作業領域、RGB、LibTorchの一時領域を確認できます。GPU全体の使用量には他プロセスも含まれます。schema 1は従来の入れ替え動作を維持します。プロファイルを追加する場合は変換元で準備し、改めて変換してください。

`python tests/shared_profiles.py --original artifacts/my-gpu --shared artifacts/my-gpu-shared`は、画像とテキストのbatch 1・4を使い、100回の切り替えで出力一致とメモリ確保量の維持を検査します。

入力順の逆転検査は、コサイン類似度0.9999以上と要素ごとの`atol=rtol=0.001`を要求し、実際の誤差を記録します。FP32 GPU演算の微小な差を許容するための条件で、CPU FP32との0.995の比較基準や実画像による検索精度検査とは別に判定します。
